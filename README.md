Рабочий прототип CRM салона красоты и бара. Node.js 22+, внешних зависимостей приложения нет. Валюта GEL (₾), время салона Asia/Tbilisi.

## Запуск и проверка

```sh
cd /workspace/sayyes
npm start
npm test
npm run preview:build
```

Сервер использует порт 3000 (`PORT` для изменения). `npm run dev` запускает перезагрузку при изменениях. Интерфейс CRM: `/`, онлайн-запись: `/book`.

Самостоятельный файл `SayYes-preview.html` содержит интерфейс, стили и общую бизнес-логику. Откройте его в браузере. Данные сохраняются в localStorage, если браузер разрешает его; иначе — только до перезагрузки. Старые данные прежнего предпросмотра дополняются новыми полями. Серверная база и база предпросмотра независимы.

## Правила расчёта

Процент зарплаты задаётся в карточке сотрудника и фиксируется при оплате. Комиссия выбранного терминала заменяет комиссию способа оплаты. Выплата зарплаты наличными уменьшает кассу; старые авансы и расходы учитываются отдельно и не создают изъятие автоматически.

Материалы в новом чеке списываются со склада услуги по FIFO. Закупки не вычитаются из результата повторно. Коэффициент потерь увеличивает стоимость, но не физическое количество списания. Бонусы начисляются на денежную часть после скидок и списания бонусов; 1 балл = 1 GEL. Уровень клиента пока является ручной меткой.

Полный возврат восстанавливает товары в исходные партии, но не расход материалов оказанных услуг. Оперативный отчёт исключает возвращённые чеки; бухгалтерский отчёт возвратов по периодам ещё не реализован. Необходимо проверить бизнес-правила перед реальными расчётами.

## Данные и доступ

Сервер атомарно сохраняет `data/salon.json` (исключён из Git). `DATA_DIR` меняет каталог. Допускается один процесс на каталог данных. Для эксплуатации нужны транзакционная БД, внешние резервные копии и мониторинг.

Публичные `/api/public-state` и `/api/manage-booking` не отдают клиентскую базу и финансовые данные. Персональная ссылка даёт право отменить конкретную запись, поэтому её нельзя публиковать.

Основной владелец входит через форму: логин `admin`, пароль из `ADMIN_PASSWORD`. Сотрудники входят по email/телефону и личному паролю после принятия приглашения. Настройка: **Команда → Доступ**. Реализованы восемь шаблонов ролей, отдельные разрешения, ограничения по сотрудникам/должностям/глубине истории, копирование и перенос доступа, отзыв приглашений и сессий. Проверки выполняются на сервере; скрытие кнопок не является защитой. [Инструкция по доступу](docs/employee-access.md).

В `NODE_ENV=production` сервер требует пароль владельца длиной не менее 12 символов и использует Secure-cookie (нужен HTTPS). В разработке без пароля и без учётных записей API открыт, создание личных входов заблокировано. Пароль задайте через секреты хостинга; не отправляйте его в чат и не добавляйте в Git. `.env.example` показывает имена параметров; локально можно запустить `node --env-file=.env server.js`. HTTP Basic сохранён для служебных запросов владельца.

Самостоятельный HTML хранит локальные демонстрационные данные и не поддерживает защищённые личные входы. Для проверки ролей запускайте сервер. Публичная эксплуатация требует HTTPS, резервных копий, мониторинга и подготовки рабочей базы.

Интеграции, фактическое списание банковских платежей, фискальные чеки, отправка сообщений, OCR, подписки и магазины приложений не подключены. Шаблоны создают только локальную очередь; заказы поставщикам — только черновики.

## Сохранение проекта

Код хранится в GitHub, локальная база и резервные копии исключены из Git. `npm run backup` создаёт проверенную локальную копию серверной базы. Подробнее: [правила хранения и восстановления](docs/storage.md). Проверки GitHub Actions запускаются при push и pull request.

Касса бара: [сценарии работы, расчёты и ограничения](docs/pos-workflow.md). Вход: **Бар → Открыть кассу**.

Запись администратора открывается кнопкой «Записать клиента». В карточке незакрытого визита можно изменить мастера, время, услугу и кресло; занятость проверяется повторно при сохранении. Добавлены четыре кресла и поиск услуг с категориями. Касса бара работает без выбора официанта; администратор фиксируется по учётной записи.

Прайс со скриншотов: 89 услуг в 13 категориях, цены «от», бесплатные услуги и длительности от 5 минут. Каталог поддерживает фильтрацию по категории и сортировку по цене/времени. [Полный список и значения для уточнения](docs/service-catalogue.md). Импорт выполняется однократно и сохраняет последующие ручные изменения.

Актуальная команда от 06.11.2026: 12 специалистов, 10 портретов. Отсутствующие в списке сотрудники архивируются с сохранением истории. Фото видны в списке, карточках, календаре, графиках и рядом с выбором мастера. Для Ирины и Федора пока показаны инициалы: исходные скриншоты не содержат их фотографий.

Карточка сотрудника: фамилия, шесть готовых должностей, базовая ставка и индивидуальные проценты по услугам/товарам. Ставки фиксируются при оплате, возврат исключает начисление; прошедшие оплаты не пересчитываются. [Правила расчёта](docs/employee-commissions.md).
